Method of representing curves and surfaces in computer graphics

</div>

**Non-uniform rational basis spline** (**NURBS**) is a mathematical
model using
<a href="//en.wikipedia.org/wiki/B-spline" id="mwDw" rel="mw:WikiLink"
title="B-spline">basis splines</a> (B-splines) that is commonly used in
<a href="//en.wikipedia.org/wiki/Computer_graphics" id="mwEA"
rel="mw:WikiLink" title="Computer graphics">computer graphics</a> for
representing curves and
<a href="//en.wikipedia.org/wiki/Surface_(mathematics)" id="mwEQ"
rel="mw:WikiLink" title="Surface (mathematics)">surfaces</a>. It offers
great flexibility and precision for handling both analytic (defined by
common mathematical
<a href="//en.wikipedia.org/wiki/Formula" id="mwEg" rel="mw:WikiLink"
title="Formula">formulae</a>) and
<a href="//en.wikipedia.org/wiki/3D_modeling" id="mwEw"
rel="mw:WikiLink" title="3D modeling">modeled shapes</a>. It is a type
of <a href="//en.wikipedia.org/wiki/3D_modeling#Process" id="mwFA"
rel="mw:WikiLink" title="3D modeling">curve modeling</a>, as opposed to
<a href="//en.wikipedia.org/wiki/Polygonal_modeling" id="mwFQ"
rel="mw:WikiLink" title="Polygonal modeling">polygonal modeling</a> or
<a href="//en.wikipedia.org/wiki/Digital_sculpting" id="mwFg"
rel="mw:WikiLink" title="Digital sculpting">digital sculpting</a>. NURBS
curves are commonly used in
<a href="//en.wikipedia.org/wiki/Computer-aided_design" id="mwFw"
rel="mw:WikiLink" title="Computer-aided design">computer-aided
design</a> (CAD),
<a href="//en.wikipedia.org/wiki/Computer-aided_manufacturing" id="mwGA"
rel="mw:WikiLink" title="Computer-aided manufacturing">manufacturing</a>
(CAM), and
<a href="//en.wikipedia.org/wiki/Computer-aided_engineering" id="mwGQ"
rel="mw:WikiLink" title="Computer-aided engineering">engineering</a>
(CAE). They are part of numerous industry-wide standards, such as
<a href="//en.wikipedia.org/wiki/IGES" id="mwGg" rel="mw:WikiLink"
title="IGES">IGES</a>,
<a href="//en.wikipedia.org/wiki/ISO_10303" id="mwGw" rel="mw:WikiLink"
title="ISO 10303">STEP</a>,
<a href="//en.wikipedia.org/wiki/ACIS" id="mwHA" rel="mw:WikiLink"
title="ACIS">ACIS</a>, and
<a href="//en.wikipedia.org/wiki/PHIGS" id="mwHQ" rel="mw:WikiLink"
title="PHIGS">PHIGS</a>. Tools for creating and editing NURBS surfaces
are found in various
<a href="//en.wikipedia.org/wiki/3D_computer_graphics_software"
id="mwHg" class="mw-redirect" rel="mw:WikiLink"
title="3D computer graphics software">3D graphics</a>,
<a href="//en.wikipedia.org/wiki/Rendering_(computer_graphics)"
id="mwHw" rel="mw:WikiLink"
title="Rendering (computer graphics)">rendering</a>, and
<a href="//en.wikipedia.org/wiki/3D_Animation" id="mwIA"
class="mw-redirect" rel="mw:WikiLink" title="3D Animation">animation</a>
software packages.

They can be efficiently handled by computer programs yet allow for easy
human interaction. NURBS surfaces are functions of two
<a href="//en.wikipedia.org/wiki/Parameter" id="mwIg" rel="mw:WikiLink"
title="Parameter">parameters</a> mapping to a surface in
<a href="//en.wikipedia.org/wiki/Three-dimensional_space" id="mwIw"
rel="mw:WikiLink" title="Three-dimensional space">three-dimensional
space</a>. The shape of the surface is determined by
<a href="//en.wikipedia.org/wiki/Control_point_(mathematics)" id="mwJA"
rel="mw:WikiLink" title="Control point (mathematics)">control points</a>.
In a compact form, NURBS surfaces can represent simple
<a href="//en.wikipedia.org/wiki/Geometric_shape" id="mwJQ"
class="mw-redirect" rel="mw:WikiLink"
title="Geometric shape">geometrical shapes</a>. For complex organic
shapes,
<a href="//en.wikipedia.org/wiki/T-Spline_(mathematics)" id="mwJg"
class="mw-redirect" rel="mw:WikiLink"
title="T-Spline (mathematics)">T-splines</a> and
<a href="//en.wikipedia.org/wiki/Subdivision_surfaces" id="mwJw"
class="mw-redirect" rel="mw:WikiLink"
title="Subdivision surfaces">subdivision surfaces</a> are more suitable
because they halve the number of control points in comparison with the
NURBS surfaces.

In general, editing NURBS curves and surfaces is intuitive and
predictable.<sup><span typeof="mw:Entity">\[</span>*<a href="//en.wikipedia.org/wiki/Wikipedia:Citation_needed"
rel="mw:WikiLink" title="Wikipedia:Citation needed"><span
title="This claim needs references to reliable sources. (January 2021)">citation
needed</span></a>*<span typeof="mw:Entity">\]</span></sup> Control
points are always either connected directly to the curve or surface, or
else act as if they were connected by a rubber band. Depending on the
type of user interface, the editing of NURBS curves and surfaces can be
via their control points (similar to
<a href="//en.wikipedia.org/wiki/Bézier_curve" id="mwKw"
rel="mw:WikiLink" title="Bézier curve">Bézier curves</a>) or via higher
level tools such as *spline modeling* and *hierarchical editing*.

## History

<span class="mw-editsection"><span class="mw-editsection-bracket">\[</span>[edit](/w/index.php?title=Non-uniform_rational_B-spline&action=edit&section=1 "Edit section: History")<span class="mw-editsection-bracket">\]</span></span>

</div>

<figure id="mwMQ" class="mw-default-size" typeof="mw:File/Thumb">
<a href="//en.wikipedia.org/wiki/File:Spline_(PSF).png" id="mwMg"
class="mw-file-description"><img
src="//upload.wikimedia.org/wikipedia/commons/thumb/f/fd/Spline_%28PSF%29.png/250px-Spline_%28PSF%29.png"

<figcaption>A <a href="//en.wikipedia.org/wiki/Flat_spline" id="mwNQ"
rel="mw:WikiLink" title="Flat spline">flat spline</a>, the physical

Before computers, designs were drawn by hand on paper with various
<a href="//en.wikipedia.org/wiki/Technical_drawing" id="mwOA"
rel="mw:WikiLink" title="Technical drawing">drafting tools</a>.
<a href="//en.wikipedia.org/wiki/Ruler" id="mwOQ" rel="mw:WikiLink"
title="Ruler">Rulers</a> were used for straight lines,
<a href="//en.wikipedia.org/wiki/Compass_(drafting)" id="mwOg"
class="mw-redirect" rel="mw:WikiLink"
title="Compass (drafting)">compasses</a> for circles, and
<a href="//en.wikipedia.org/wiki/Protractor" id="mwOw"
class="mw-redirect" rel="mw:WikiLink" title="Protractor">protractors</a>
for angles. But many shapes, such as the
<a href="//en.wikipedia.org/wiki/Freeform_curve" id="mwPA"
class="mw-redirect" rel="mw:WikiLink" title="Freeform curve">freeform
curve</a> of a ship's bow, could not be drawn with these tools.

Although such curves could be drawn freehand at the drafting board,
shipbuilders often needed a life-size version which could not be done by
hand. Such large drawings were done with the help of flexible strips of
wood, called splines. The splines were held in place at a number of
predetermined points, by lead "ducks", named for the bill-shaped
protrusion that the splines rested against. Between the ducks, the
<a href="//en.wikipedia.org/wiki/Elasticity_(physics)" id="mwPg"
rel="mw:WikiLink" title="Elasticity (physics)">elasticity</a> of the
spline material caused the strip to take the shape that minimized the
energy of bending, thus creating the smoothest possible shape that fit
the constraints. The shape could be adjusted by moving the
ducks.<sup><a href="#cite_note-mactech-1" id="mwPw"><span id="mwQA"
class="mw-reflink-text"><span id="mwQQ"
class="cite-bracket">[</span>1<span id="mwQg"
class="cite-bracket">]</span></span></a><a href="#cite_note-2" id="mwQw"><span id="mwRA"
class="mw-reflink-text"><span id="mwRQ"
class="cite-bracket">[</span>2<span id="mwRg"
class="cite-bracket">]</span></span></a></sup>

In 1964, mathematicians started studying the spline shape, and derived
the piecewise
<a href="//en.wikipedia.org/wiki/Polynomial" id="mwSA" rel="mw:WikiLink"
title="Polynomial">polynomial</a> formula known as the
<a href="//en.wikipedia.org/wiki/Spline_(mathematics)" id="mwSQ"
rel="mw:WikiLink" title="Spline (mathematics)">spline curve</a> or
spline function.
<a href="//en.wikipedia.org/wiki/Isaac_Jacob_Schoenberg" id="mwSg"
rel="mw:WikiLink" title="Isaac Jacob Schoenberg">I. J. Schoenberg</a>
gave the spline function its name after its resemblance to the
mechanical spline used by
draftsmen.<sup><a href="#cite_note-3" id="mwSw"><span id="mwTA"
class="mw-reflink-text"><span id="mwTQ"
class="cite-bracket">[</span>3<span id="mwTg"
class="cite-bracket">]</span></span></a></sup>

As computers were introduced into the design process, the physical
properties of such splines were investigated so that they could be
modelled with mathematical precision and reproduced where needed.
Pioneering work was done in
<a href="//en.wikipedia.org/wiki/France" id="mwUA" rel="mw:WikiLink"
title="France">France</a> by
<a href="//en.wikipedia.org/wiki/Renault" id="mwUQ" rel="mw:WikiLink"
title="Renault">Renault</a> engineer
<a href="//en.wikipedia.org/wiki/Pierre_Bézier" id="mwUg"
rel="mw:WikiLink" title="Pierre Bézier">Pierre Bézier</a>, and
<a href="//en.wikipedia.org/wiki/Citroën" id="mwUw" rel="mw:WikiLink"
title="Citroën">Citroën</a>'s physicist and mathematician
<a href="//en.wikipedia.org/wiki/Paul_de_Casteljau" id="mwVA"
rel="mw:WikiLink" title="Paul de Casteljau">Paul de Casteljau</a>. They
worked nearly parallel to each other, but because Bézier published the
results of his work, Bézier curves were named after him, while de
Casteljau's name is only associated with related algorithms.

Bézier's work reached a group of faculty and graduate students at
Syracuse University, including
<a href="//en.wikipedia.org/wiki/Steven_Anson_Coons" id="mwVg"
rel="mw:WikiLink" title="Steven Anson Coons">Steven Anson Coons</a>,
William Gordon, Robin Forrest, Rich Riesenfeld, and Ken Versprille.
Riesenfeld's dissertation introduced
<a href="//en.wikipedia.org/wiki/B-spline" id="mwVw" rel="mw:WikiLink"
title="B-spline">B-splines</a>; Versprille's dissertation generalized
them to be non-uniform and
rational.<sup><a href="#cite_note-4" id="mwWA"><span id="mwWQ"
class="mw-reflink-text"><span id="mwWg"
class="cite-bracket">[</span>4<span id="mwWw"
class="cite-bracket">]</span></span></a></sup> Riesenfeld moved to the
<a href="//en.wikipedia.org/wiki/University_of_Utah" id="mwXA"
rel="mw:WikiLink" title="University of Utah">University of Utah</a>,
where one of his students went on to work at
<a href="//en.wikipedia.org/wiki/Boeing" id="mwXQ" rel="mw:WikiLink"
title="Boeing">Boeing</a>, which needed a generalized way to exactly
represent various other formulas in
use.<sup><a href="#cite_note-5" id="mwXg"><span id="mwXw"
class="mw-reflink-text"><span id="mwYA"
class="cite-bracket">[</span>5<span id="mwYQ"
class="cite-bracket">]</span></span></a></sup> Boeing adopted
Versprille's concept, abbreviated it to "NURBS", integrated it into
their <a href="//en.wikipedia.org/wiki/Computer-aided_design" id="mwYg"
rel="mw:WikiLink" title="Computer-aided design">CAD</a> program TIGER,
and proposed it as an industry
standard.<sup><a href="#cite_note-6" id="mwYw"><span id="mwZA"
class="mw-reflink-text"><span id="mwZQ"
class="cite-bracket">[</span>6<span id="mwZg"
class="cite-bracket">]</span></span></a></sup>

Real-time, interactive rendering of NURBS curves and surfaces was first
made commercially available on
<a href="//en.wikipedia.org/wiki/Silicon_Graphics" id="mwaA"
rel="mw:WikiLink" title="Silicon Graphics">Silicon Graphics</a>
workstations in 1989. In 1993, the first interactive NURBS modeller for
PCs, called NöRBS, was developed by CAS Berlin, a small
<a href="//en.wikipedia.org/wiki/Startup_company" id="mwaQ"
rel="mw:WikiLink" title="Startup company">startup company</a>
cooperating with
<a href="//en.wikipedia.org/wiki/Technische_Universität_Berlin"
id="mwag" rel="mw:WikiLink"
title="Technische Universität Berlin">Technische Universität Berlin</a>.<sup><span typeof="mw:Entity">\[</span>*<a href="//en.wikipedia.org/wiki/Wikipedia:Citation_needed"
rel="mw:WikiLink" title="Wikipedia:Citation needed"><span
title="This claim needs references to reliable sources. (August 2023)">citation
needed</span></a>*<span typeof="mw:Entity">\]</span></sup>

## Continuity

<span class="mw-editsection"><span class="mw-editsection-bracket">\[</span>[edit](/w/index.php?title=Non-uniform_rational_B-spline&action=edit&section=2 "Edit section: Continuity")<span class="mw-editsection-bracket">\]</span></span>

</div>

<span id="mwbg" class="mw-empty-elt" about="#mwt24"
typeof="mw:Transclusion"
mw="{&quot;parts&quot;:[{&quot;template&quot;:{&quot;target&quot;:{&quot;wt&quot;:&quot;Main&quot;,&quot;href&quot;:&quot;./Template:Main&quot;},&quot;params&quot;:{&quot;1&quot;:{&quot;wt&quot;:&quot;Smooth function&quot;}},&quot;i&quot;:0}}]}"></span><style data-mw-deduplicate="TemplateStyles:r1353705441" typeof="mw:Extension/templatestyles" about="#mwt25" data-mw="{&quot;name&quot;:&quot;templatestyles&quot;,&quot;attrs&quot;:{&quot;src&quot;:&quot;Module:Hatnote/styles.css&quot;},&quot;body&quot;:{&quot;extsrc&quot;:&quot;&quot;}}">.mw-parser-output .hatnote{font-style:italic}.mw-parser-output div.hatnote{padding-left:1.6em;margin-bottom:0.5em}.mw-parser-output .hatnote i{font-style:normal}.mw-parser-output .hatnote+span.mw-empty-elt+.hatnote,.mw-parser-output .hatnote+link+.hatnote{margin-top:-0.5em}@media print{body.ns-0 .mw-parser-output .hatnote{display:none!important}}</style>

<div id="mwbw" class="hatnote navigation-not-searchable" role="note"
about="#mwt24">

Main article:
<a href="//en.wikipedia.org/wiki/Smooth_function" class="mw-redirect"
rel="mw:WikiLink" title="Smooth function">Smooth function</a>

</div>

A surface under construction, e.g. the hull of a motor yacht, is usually
composed of several NURBS surfaces known as **NURBS patches** (or just
*patches*). These
<a href="//en.wikipedia.org/wiki/Surface_patch" id="mwcw"
class="mw-redirect" rel="mw:WikiLink" title="Surface patch">surface
patches</a> should be fitted together in such a way that the boundaries
are invisible. This is mathematically expressed by the concept of
<a href="//en.wikipedia.org/wiki/Geometric_continuity" id="mwdA"
class="mw-redirect" rel="mw:WikiLink"
title="Geometric continuity">geometric continuity</a>.

Higher-level tools exist that benefit from the ability of NURBS to
create and establish geometric continuity of different levels:

**Positional continuity**  
(G<sup>0</sup>) holds whenever the end positions of two curves or
surfaces coincide. The curves or surfaces may still meet at an angle,
giving rise to a sharp corner or edge and causing broken highlights.

**Tangential continuity**  
(G¹) requires the end vectors of the curves or surfaces to be parallel
and pointing the same way, ruling out sharp edges. Because highlights
falling on a tangentially continuous edge are always continuous and thus
look natural, this level of continuity can often be sufficient.

**Curvature continuity**  
(G²) further requires the end vectors to be of the same length and rate
of length change. Highlights falling on a curvature-continuous edge do
not display any change, causing the two surfaces to appear as one. This
can be visually recognized as "perfectly smooth". This level of
continuity is very useful in the creation of models that require many
<a href="//en.wikipedia.org/wiki/Bi-cubic" id="mwgQ" class="mw-redirect"
rel="mw:WikiLink" title="Bi-cubic">bi-cubic</a> patches composing one
continuous surface.

Geometric continuity mainly refers to the shape of the resulting
surface; since NURBS surfaces are functions, it is also possible to
discuss the derivatives of the surface with respect to the parameters.
This is known as
<a href="//en.wikipedia.org/wiki/Parametric_continuity" id="mwgw"
rel="mw:WikiLink" title="Parametric continuity">parametric
continuity</a>. Parametric continuity of a given degree implies
geometric continuity of that degree.

First- and second-level parametric continuity (C<sup>0</sup> and C¹) are
for practical purposes identical to positional and tangential
(G<sup>0</sup> and G¹) continuity. Third-level parametric continuity
(C²), however, differs from curvature continuity in that its
parameterization is also continuous. In practice, C² continuity is
easier to achieve if uniform B-splines are used.

The definition of C<sup>*n*</sup> continuity requires that the *n*th
derivative of adjacent curves/surfaces (<span id="mwiw"
class="mwe-math-element mwe-math-element-inline"
typeof="mw:Extension/math" about="#mwt26"
mw="{&quot;name&quot;:&quot;math&quot;,&quot;attrs&quot;:{},&quot;body&quot;:{&quot;extsrc&quot;:&quot;d^n C(u)/du^n&quot;}}"><span class="mwe-math-mathml-inline mwe-math-mathml-a11y"
style="display: none;">$`{\displaystyle d^{n}C(u)/du^{n}}`$</span><img
src="https://wikimedia.org/api/rest_v1/media/math/render/svg/2a773acb16a418043cdccd31d3902d3934db668c"
class="mwe-math-fallback-image-inline mw-invert skin-invert"
style="vertical-align: -0.838ex; width:12.268ex; height:2.843ex;"
aria-hidden="true" alt="{\displaystyle d^{n}C(u)/du^{n}}" /></span>) are
equal at a joint.<sup><a href="#cite_note-7" id="mwjA"><span id="mwjQ"
class="mw-reflink-text"><span id="mwjg"
class="cite-bracket">[</span>7<span id="mwjw"
class="cite-bracket">]</span></span></a></sup> Note that the (partial)
derivatives of curves and surfaces are vectors that have a direction and
a magnitude; both should be equal.

Highlights and reflections can reveal the perfect smoothing, which is
otherwise practically impossible to achieve without NURBS surfaces that
have at least G² continuity. This same principle is used as one of the
surface evaluation methods whereby a
<a href="//en.wikipedia.org/wiki/Ray_tracing_(graphics)" id="mwkQ"
rel="mw:WikiLink" title="Ray tracing (graphics)">ray-traced</a> or
<a href="//en.wikipedia.org/wiki/Reflection_mapping" id="mwkg"
rel="mw:WikiLink" title="Reflection mapping">reflection-mapped</a> image
of a surface with white stripes reflecting on it will show even the
smallest deviations on a surface or set of surfaces. This method is
derived from car prototyping wherein surface quality is inspected by
checking the quality of reflections of a neon-light ceiling on the car
surface. This method is also known as "Zebra analysis".

</div>

## Technical specifications

<span class="mw-editsection"><span class="mw-editsection-bracket">\[</span>[edit](/w/index.php?title=Non-uniform_rational_B-spline&action=edit&section=3 "Edit section: Technical specifications")<span class="mw-editsection-bracket">\]</span></span>

</div>

<figure id="mwlA" class="mw-halign-right" typeof="mw:File">
<a href="//en.wikipedia.org/wiki/File:Surface_modelling.svg" id="mwlQ"
class="mw-file-description"><img

A NURBS curve is defined by its order, a set of weighted control points,
and a knot vector.<sup><a href="#cite_note-8" id="mwmQ"><span id="mwmg"
class="mw-reflink-text"><span id="mwmw"
class="cite-bracket">[</span>8<span id="mwnA"
class="cite-bracket">]</span></span></a></sup> NURBS curves and surfaces
are generalizations of both
<a href="//en.wikipedia.org/wiki/B-spline" id="mwnQ" rel="mw:WikiLink"
title="B-spline">B-splines</a> and
<a href="//en.wikipedia.org/wiki/Bézier_curve" id="mwng"
rel="mw:WikiLink" title="Bézier curve">Bézier curves</a> and surfaces,
the primary difference being the weighting of the control points, which
makes NURBS curves *rational*.

(*Non-rational*, aka *simple*, B-splines are a special case/subset of
rational B-splines, where each control point is a regular non-homogenous
coordinate \[no 'w'\] rather than a
<a href="//en.wikipedia.org/wiki/Homogeneous_coordinates" id="mwow"
rel="mw:WikiLink" title="Homogeneous coordinates">homogeneous
coordinate</a>.<sup><a href="#cite_note-9" id="mwpA"><span id="mwpQ"
class="mw-reflink-text"><span id="mwpg"
class="cite-bracket">[</span>9<span id="mwpw"
class="cite-bracket">]</span></span></a></sup> That is equivalent to
having weight "1" at each control point; *Rational* B-splines use the
'w' of each control point as a
**weight**.<sup><a href="#cite_note-10" id="mwqg"><span id="mwqw"
class="mw-reflink-text"><span id="mwrA"
class="cite-bracket">[</span>10<span id="mwrQ"
class="cite-bracket">]</span></span></a></sup>)

By using a two-dimensional grid of control points, NURBS surfaces
including planar patches and sections of spheres can be created. These
are parametrized with two variables (typically called *s* and *t* or *u*
and *v*). This can be extended to arbitrary dimensions to create NURBS
mapping <span id="mwsw" class="mwe-math-element mwe-math-element-inline"
typeof="mw:Extension/math" about="#mwt37"
mw="{&quot;name&quot;:&quot;math&quot;,&quot;attrs&quot;:{},&quot;body&quot;:{&quot;extsrc&quot;:&quot;\\Reals^n \\to \\Reals^n&quot;}}"><span class="mwe-math-mathml-inline mwe-math-mathml-a11y"
style="display: none;">$`{\displaystyle \mathbb {R} ^{n}\to \mathbb {R} ^{n}}`$</span><img
src="https://wikimedia.org/api/rest_v1/media/math/render/svg/aedfe8fbd4f4cf7ee069b4200e65cd7d2657279f"
class="mwe-math-fallback-image-inline mw-invert skin-invert"
style="vertical-align: -0.338ex; width:9.407ex; height:2.343ex;"
aria-hidden="true"
alt="{\displaystyle \mathbb {R} ^{n}\to \mathbb {R} ^{n}}" /></span>.

NURBS curves and surfaces are useful for a number of reasons:

- <span id="mwtg">The set of NURBS for a given order is
  <a href="//en.wikipedia.org/wiki/Invariant_(mathematics)" id="mwtw"
  rel="mw:WikiLink" title="Invariant (mathematics)">invariant</a> under
  <a href="//en.wikipedia.org/wiki/Affine_transformation" id="mwuA"
  rel="mw:WikiLink" title="Affine transformation">affine</a>
  transformations:<sup><a href="#cite_note-11" id="mwuQ"><span id="mwug"
  class="mw-reflink-text"><span id="mwuw"
  class="cite-bracket">[</span>11<span id="mwvA"
  class="cite-bracket">]</span></span></a></sup> operations like
  rotations and translations can be applied to NURBS curves and surfaces
  by applying them to their control points.</span>
- <span id="mwvQ">They offer one common mathematical form for both
  standard analytical shapes (e.g.,
  <a href="//en.wikipedia.org/wiki/Conic" id="mwvg" class="mw-redirect"
  rel="mw:WikiLink" title="Conic">conics</a>) and free-form
  shapes.</span>
- <span id="mwvw">They provide the flexibility to design a large variety
  of shapes.</span>
- <span id="mwwA">They reduce the memory consumption when storing shapes
  (compared to simpler methods).</span>
- <span id="mwwQ">They can be evaluated reasonably quickly by
  <a href="//en.wikipedia.org/wiki/Numerically_stable" id="mwwg"
  class="mw-redirect" rel="mw:WikiLink"
  title="Numerically stable">numerically stable</a> and accurate
  <a href="//en.wikipedia.org/wiki/Algorithm" id="mwww" rel="mw:WikiLink"
  title="Algorithm">algorithms</a>.</span>

Here, NURBS is mostly discussed in one dimension (curves); it can be
generalized to two (surfaces) or even more dimensions.

<div id="mwxQ" class="section" mw-section-id="4"
aria-labelledby="Order">

<div class="mw-heading mw-heading3">

### Order

<span class="mw-editsection"><span class="mw-editsection-bracket">\[</span>[edit](/w/index.php?title=Non-uniform_rational_B-spline&action=edit&section=4 "Edit section: Order")<span class="mw-editsection-bracket">\]</span></span>

</div>

The *order* of a NURBS curve defines the number of nearby control points
that influence any given point on the curve. The curve is represented
mathematically by a polynomial of degree one less than the order of the
curve. Hence, second-order curves (which are represented by linear
polynomials) are called linear curves, third-order curves are called
quadratic curves, and fourth-order curves are called cubic curves. The
number of control points must be greater than or equal to the order of
the curve.

In practice, cubic curves are the ones most commonly used. Fifth- and
sixth-order curves are sometimes useful, especially for obtaining
continuous higher order derivatives, but curves of higher orders are
practically never used because they lead to internal numerical problems
and tend to require disproportionately large calculation times.

</div>

separate square below the control cage delineates the X and Y extents of
the surface.</figcaption>
</figure>

The control points determine the shape of the
curve.<sup><a href="#cite_note-12" id="mwzw"><span id="mw0A"
class="mw-reflink-text"><span id="mw0Q"
class="cite-bracket">[</span>12<span id="mw0g"
class="cite-bracket">]</span></span></a></sup> Typically, each point of
the curve is computed by taking a
<a href="//en.wikipedia.org/wiki/Weighted" id="mw0w" class="mw-redirect"
rel="mw:WikiLink" title="Weighted">weighted</a> sum of a number of
control points. The weight of each point varies according to the
governing parameter. For a curve of degree d, the weight of any control
point is only nonzero in d+1 intervals of the
<a href="//en.wikipedia.org/wiki/Parameter_space" id="mw1A"
rel="mw:WikiLink" title="Parameter space">parameter space</a>. Within
those intervals, the weight changes according to a polynomial function
(*basis functions*) of degree d. At the boundaries of the intervals, the
basis functions go smoothly to zero, the smoothness being determined by
the degree of the polynomial.

As an example, the
<a href="//en.wikipedia.org/wiki/Basis_function" id="mw1w"
rel="mw:WikiLink" title="Basis function">basis function</a> of degree
one is a triangle function. It rises from zero to one, then falls to
zero again. While it rises, the basis function of the previous control
point falls. In that way, the curve interpolates between the two points,
and the resulting curve is a polygon, which is
<a href="//en.wikipedia.org/wiki/Continuous_function" id="mw2A"
rel="mw:WikiLink" title="Continuous function">continuous</a>, but not
<a href="//en.wikipedia.org/wiki/Differentiable_function" id="mw2Q"
rel="mw:WikiLink" title="Differentiable function">differentiable</a> at
the interval boundaries, or knots. Higher degree polynomials have
correspondingly more continuous derivatives. Note that within the
interval the polynomial nature of the basis functions and the linearity
of the construction make the curve perfectly smooth, so it is only at
the knots that discontinuity can arise.

In many applications the fact that a single control point only
influences those intervals where it is active is a highly desirable
property, known as **local support**. In modeling, it allows the
changing of one part of a surface while keeping other parts unchanged.

Adding more control points allows better approximation to a given curve,
although only a certain class of curves can be represented exactly with
a finite number of control points. NURBS curves also feature a scalar
**weight** for each control point. This allows for more control over the
shape of the curve without unduly raising the number of control points.
In particular, it adds conic sections like circles and ellipses to the
set of curves that can be represented exactly. The term *rational* in
NURBS refers to these weights.

The control points can have any
<a href="//en.wikipedia.org/wiki/Dimensionality" id="mw4A"
class="mw-redirect" rel="mw:WikiLink"
title="Dimensionality">dimensionality</a>. One-dimensional points just
define a
<a href="//en.wikipedia.org/wiki/Scalar_(mathematics)" id="mw4Q"
rel="mw:WikiLink" title="Scalar (mathematics)">scalar</a> function of
the parameter. These are typically used in image processing programs to
tune the brightness and color curves. Three-dimensional control points
are used abundantly in 3D modeling, where they are used in the everyday
meaning of the word 'point', a location in 3D space. Multi-dimensional
points might be used to control sets of time-driven values, e.g. the
different positional and rotational settings of a robot arm. NURBS
surfaces are just an application of this. Each control 'point' is
actually a full vector of control points, defining a curve. These curves
share their degree and the number of control points, and span one
dimension of the parameter space. By interpolating these control vectors
over the other dimension of the parameter space, a continuous set of
curves is obtained, defining the surface.

</div>

<div id="mw4g" class="section" mw-section-id="6"
aria-labelledby="Knot_vector">

<div class="mw-heading mw-heading3">

### Knot vector

<span class="mw-editsection"><span class="mw-editsection-bracket">\[</span>[edit](/w/index.php?title=Non-uniform_rational_B-spline&action=edit&section=6 "Edit section: Knot vector")<span class="mw-editsection-bracket">\]</span></span>

</div>

The knot vector is a sequence of parameter values that determines where
and how the control points affect the NURBS curve. The number of knots
is always equal to the number of control points plus curve degree plus
one (i.e. number of control points plus curve order). The knot vector
divides the parametric space in the intervals mentioned before, usually
referred to as *knot spans*. Each time the parameter value enters a new
knot span, a new control point becomes active, while an old control
point is discarded. It follows that the values in the knot vector should
be in nondecreasing order, so (0, 0, 1, 2, 3, 3) is valid while (0, 0,
2, 1, 3, 3) is not.

Consecutive knots can have the same value. This then defines a knot span
of zero length, which implies that two control points are activated at
the same time (and of course two control points become deactivated).
This has impact on continuity of the resulting curve or its higher
derivatives; for instance, it allows the creation of corners in an
otherwise smooth NURBS curve. A number of coinciding knots is sometimes
referred to as a knot with a certain **multiplicity**. Knots with
multiplicity two or three are known as double or triple knots. The
multiplicity of a knot is limited to the degree of the curve; since a
higher multiplicity would split the curve into disjoint parts and it
would leave control points unused. For first-degree NURBS, each knot is
paired with a control point.

The knot vector usually starts with a knot that has multiplicity equal
to the order. This makes sense, since this activates the control points
that have influence on the first knot span. Similarly, the knot vector
usually ends with a knot of that multiplicity. Curves with such knot
vectors start and end in a control point.

The values of the knots control the mapping between the input parameter
and the corresponding NURBS value. For example, if a NURBS describes a
path through space over time, the knots control the time that the
function proceeds past the control points. For the purposes of
representing shapes, however, only the ratios of the difference between
the knot values matter; in that case, the knot vectors (0, 0, 1, 2, 3,
3) and (0, 0, 2, 4, 6, 6) produce the same curve. The positions of the
knot values influences the mapping of parameter space to curve space.
Rendering a NURBS curve is usually done by stepping with a fixed stride
through the parameter range. By changing the knot span lengths, more
sample points can be used in regions where the curvature is high.
Another use is in situations where the parameter value has some physical
significance, for instance if the parameter is time and the curve
describes the motion of a robot arm. The knot span lengths then
translate into velocity and acceleration, which are essential to get
right to prevent damage to the robot arm or its environment. This
flexibility in the mapping is what the phrase *non uniform* in NURBS
refers to.

Necessary only for internal calculations, knots are usually not helpful
to the users of modeling software. Therefore, many modeling applications
do not make the knots editable or even visible. It's usually possible to
establish reasonable knot vectors by looking at the variation in the
control points. More recent versions of NURBS software (e.g.,
<a href="//en.wikipedia.org/wiki/Autodesk_Maya" id="mw6w"
rel="mw:WikiLink" title="Autodesk Maya">Autodesk Maya</a> and
<a href="//en.wikipedia.org/wiki/Rhinoceros_3D" id="mw7A"
rel="mw:WikiLink" title="Rhinoceros 3D">Rhinoceros 3D</a>) allow for
interactive editing of knot positions, but this is significantly less
intuitive than the editing of control points.

</div>

One knot span is considerably shorter than the others. On that knot
span, the peak in the quadratic basis function is more distinct,
reaching almost one. Conversely, the adjoining basis functions fall to
zero more quickly. In the geometrical interpretation, this means that
the curve approaches the corresponding control point closely. In case of
a double knot, the length of the knot span becomes zero and the peak
reaches one exactly. The basis function is no longer differentiable at
that point. The curve will have a sharp corner if the neighbour control
points are not collinear.

A number of transformations can be applied to a NURBS object. For

position and a knot is inserted in the knot vector. These manipulations
are used extensively during interactive design. When adding a control
point, the shape of the curve should stay the same, forming the starting
point for further adjustments. A number of these operations are

### Knot insertion

<span class="mw-editsection"><span class="mw-editsection-bracket">\[</span>[edit](/w/index.php?title=Non-uniform_rational_B-spline&action=edit&section=11 "Edit section: Knot insertion")<span class="mw-editsection-bracket">\]</span></span>

</div>

be achieved by an algorithm that is more efficient than repeated knot

</div>

<div id="mwAV8" class="section" mw-section-id="12"
aria-labelledby="Knot_removal">

<div class="mw-heading mw-heading3">

### Knot removal

<span class="mw-editsection"><span class="mw-editsection-bracket">\[</span>[edit](/w/index.php?title=Non-uniform_rational_B-spline&action=edit&section=12 "Edit section: Knot removal")<span class="mw-editsection-bracket">\]</span></span>

</div>

**Knot removal** is the reverse of knot insertion. Its purpose is to
remove knots and the associated control points in order to get a more
compact representation. Obviously, this is not always possible while
retaining the exact shape of the curve. In practice, a tolerance in the
accuracy is used to determine whether a knot can be removed. The process
is used to clean up after an interactive session in which control points
may have been added manually, or after importing a curve from a
different representation, where a straightforward conversion process
leads to redundant control points.

</div>

<div id="mwAWI" class="section" mw-section-id="13"
aria-labelledby="Degree_elevation">

<div class="mw-heading mw-heading3">

### Degree elevation

<span class="mw-editsection"><span class="mw-editsection-bracket">\[</span>[edit](/w/index.php?title=Non-uniform_rational_B-spline&action=edit&section=13 "Edit section: Degree elevation")<span class="mw-editsection-bracket">\]</span></span>

</div>

A NURBS curve of a particular degree can always be represented by a
NURBS curve of higher degree. This is frequently used when combining
separate NURBS curves, e.g., when creating a NURBS surface interpolating
between a set of NURBS curves or when unifying adjacent curves. In the
process, the different curves should be brought to the same degree,
usually the maximum degree of the set of curves. The process is known as
**degree elevation**.

</div>

The order is three, since a circle is a quadratic curve and the spline's
order is one more than the degree of its piecewise polynomial segments.
The knot vector is <span id="mwAbY"
class="mwe-math-element mwe-math-element-inline"
typeof="mw:Extension/math" about="#mwt110"
mw="{&quot;name&quot;:&quot;math&quot;,&quot;attrs&quot;:{},&quot;body&quot;:{&quot;extsrc&quot;:&quot;\\{0, 0, 0, \\pi/2, \\pi/2, \\pi, \\pi, 3\\pi/2, 3\\pi/2, 2\\pi, 2\\pi, 2\\pi\\}\\,&quot;}}"><span class="mwe-math-mathml-inline mwe-math-mathml-a11y"
style="display: none;">$`{\displaystyle \{0,0,0,\pi /2,\pi /2,\pi ,\pi ,3\pi /2,3\pi /2,2\pi ,2\pi ,2\pi \}\,}`$</span><img
src="https://wikimedia.org/api/rest_v1/media/math/render/svg/6ce3e2588b1653713c70116f5b7854f64dc3a1eb"
class="mwe-math-fallback-image-inline mw-invert skin-invert"
style="vertical-align: -0.838ex; width:44.673ex; height:2.843ex;"
aria-hidden="true"
alt="{\displaystyle \{0,0,0,\pi /2,\pi /2,\pi ,\pi ,3\pi /2,3\pi /2,2\pi ,2\pi ,2\pi \}\,}" /></span>.
The circle is composed of four quarter circles, tied together with
double knots. Although double knots in a third order NURBS curve would
normally result in loss of continuity in the first derivative, the
control points are positioned in such a way that the first derivative is
continuous. In fact, the curve is infinitely differentiable everywhere,
as it must be if it exactly represents a circle.

The curve represents a circle exactly, but it is not exactly
parametrized in the circle's arc length. This means, for example, that
the point at <span id="mwAbg"
class="mwe-math-element mwe-math-element-inline"
typeof="mw:Extension/math" about="#mwt111"
mw="{&quot;name&quot;:&quot;math&quot;,&quot;attrs&quot;:{},&quot;body&quot;:{&quot;extsrc&quot;:&quot;t&quot;}}"><span class="mwe-math-mathml-inline mwe-math-mathml-a11y"
style="display: none;">$`{\displaystyle t}`$</span><img
src="https://wikimedia.org/api/rest_v1/media/math/render/svg/65658b7b223af9e1acc877d848888ecdb4466560"
class="mwe-math-fallback-image-inline mw-invert skin-invert"
style="vertical-align: -0.338ex; width:0.84ex; height:2.009ex;"
aria-hidden="true" alt="{\displaystyle t}" /></span> does not lie at
<span id="mwAbk" class="mwe-math-element mwe-math-element-inline"
typeof="mw:Extension/math" about="#mwt112"
mw="{&quot;name&quot;:&quot;math&quot;,&quot;attrs&quot;:{},&quot;body&quot;:{&quot;extsrc&quot;:&quot;(\\sin(t), \\cos(t))&quot;}}"><span class="mwe-math-mathml-inline mwe-math-mathml-a11y"
style="display: none;">$`{\displaystyle (\sin(t),\cos(t))}`$</span><img
src="https://wikimedia.org/api/rest_v1/media/math/render/svg/44b7cd88d94b0c1456d5a87c4154fe5737496c47"
class="mwe-math-fallback-image-inline mw-invert skin-invert"
style="vertical-align: -0.838ex; width:14.108ex; height:2.843ex;"
aria-hidden="true" alt="{\displaystyle (\sin(t),\cos(t))}" /></span>
(except for the start, middle and end point of each quarter circle,
since the representation is symmetrical). This would be impossible,
since the *x* coordinate of the circle would provide an exact rational
polynomial expression for <span id="mwAbs"
class="mwe-math-element mwe-math-element-inline"
typeof="mw:Extension/math" about="#mwt113"
mw="{&quot;name&quot;:&quot;math&quot;,&quot;attrs&quot;:{},&quot;body&quot;:{&quot;extsrc&quot;:&quot;\\cos(t)&quot;}}"><span class="mwe-math-mathml-inline mwe-math-mathml-a11y"
style="display: none;">$`{\displaystyle \cos(t)}`$</span><img
src="https://wikimedia.org/api/rest_v1/media/math/render/svg/f3e085ea72cfc97b8a3ed794d63f7f799e76c2fc"
class="mwe-math-fallback-image-inline mw-invert skin-invert"
style="vertical-align: -0.838ex; width:5.76ex; height:2.843ex;"
aria-hidden="true" alt="{\displaystyle \cos(t)}" /></span>, which is
impossible. The circle does make one full revolution as its parameter
<span id="mwAbw" class="mwe-math-element mwe-math-element-inline"
typeof="mw:Extension/math" about="#mwt114"
mw="{&quot;name&quot;:&quot;math&quot;,&quot;attrs&quot;:{},&quot;body&quot;:{&quot;extsrc&quot;:&quot;t&quot;}}"><span class="mwe-math-mathml-inline mwe-math-mathml-a11y"
style="display: none;">$`{\displaystyle t}`$</span><img
src="https://wikimedia.org/api/rest_v1/media/math/render/svg/65658b7b223af9e1acc877d848888ecdb4466560"
class="mwe-math-fallback-image-inline mw-invert skin-invert"
style="vertical-align: -0.338ex; width:0.84ex; height:2.009ex;"
aria-hidden="true" alt="{\displaystyle t}" /></span> goes from 0 to
<span id="mwAb0" class="mwe-math-element mwe-math-element-inline"
typeof="mw:Extension/math" about="#mwt115"
mw="{&quot;name&quot;:&quot;math&quot;,&quot;attrs&quot;:{},&quot;body&quot;:{&quot;extsrc&quot;:&quot;2\\pi&quot;}}"><span class="mwe-math-mathml-inline mwe-math-mathml-a11y"
style="display: none;">$`{\displaystyle 2\pi }`$</span><img

style="vertical-align: -0.338ex; width:2.494ex; height:2.176ex;"
aria-hidden="true" alt="{\displaystyle 2\pi }" /></span>, but this is
only because the knot vector was arbitrarily chosen as multiples of
<span id="mwAb4" class="mwe-math-element mwe-math-element-inline"
typeof="mw:Extension/math" about="#mwt116"
