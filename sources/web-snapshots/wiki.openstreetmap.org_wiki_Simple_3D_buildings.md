This page describes tags for basic 3D attributes of
[buildings](/wiki/Buildings "Buildings"). This description scheme is
therefore limited, not all details can be described by it. You can
report cases of complex edits [on the talk
page](/wiki/Talk:Simple_3D_Buildings#Limitations "Talk:Simple 3D Buildings")
or consult the page [F3DB](/wiki/F3DB "F3DB") (Full 3D Building) for 3D
mapping proposals advanced.

The following tagging methods are results of the [2nd 3D Workshop
Garching](/wiki/2nd_3D_Workshop_Garching "2nd 3D Workshop Garching"),
where most 3D developers agreed on supporting a unified subset of tags
in their programs. Basically, we describe the volume of a building using
two types of areas: 1) building outlines
([`building`](/wiki/Key:building "Key:building")`=*`) for the most
general area of a complex building and 2) building parts
([`building:part`](/wiki/Key:building:part "Key:building:part")`=*`) to
describe sections of the building, especially those with different
height or other attributes.

## <span id="How_to_map" class="mw-headline">How to map</span>

### <span id="Building_outlines" class="mw-headline">Building outlines</span>

<figure class="mw-default-size" typeof="mw:File/Thumb">
<a href="/wiki/File:Building_part_areas_in_building_area.svg"
class="mw-file-description"><img
src="/w/images/thumb/3/36/Building_part_areas_in_building_area.svg/330px-Building_part_areas_in_building_area.svg.png"
class="mw-file-element" decoding="async"
srcset="/w/images/thumb/3/36/Building_part_areas_in_building_area.svg/500px-Building_part_areas_in_building_area.svg.png 1.5x, /w/images/thumb/3/36/Building_part_areas_in_building_area.svg/960px-Building_part_areas_in_building_area.svg.png 2x"
width="300" height="268" /></a>
<figcaption>Two building:part areas (green) within a building area
(red). Gaps between polygons are illustrative only, in reality their
sides match precisely.</figcaption>
</figure>

The building outline represents the area of land covered by the union of
all parts of the building. The outline may in most cases also be
considered the building footprint. This is a closed way or
[multipolygon](/wiki/Relation:multipolygon "Relation:multipolygon")
tagged with [`building`](/wiki/Key:building "Key:building")`=*`.

Building attributes (e.g., address, name, overall height, operator,
etc.) must be tagged on this building outline. A building should have a
single area tagged [`building`](/wiki/Key:building "Key:building")`=*`.

The building outline provides backward compatibility for 2D rendering
software, such as Mapnik, and other data consumers not interested in 3D
modeling. When a building has any
[`building:part`](/wiki/Key:building:part "Key:building:part")`=*`
areas, the building outline is not considered for 3D
rendering<sup>[<span class="cite-bracket">\[</span>1<span class="cite-bracket">\]</span>](#cite_note-1)</sup>.

### <span id="Building_parts" class="mw-headline">Building parts</span>

Parts of a building that have differing physical characteristics
(height, color, etc) are usually modeled by drawing an area within the
building outline tagged with the
[`building:part`](/wiki/Key:building:part "Key:building:part")`=*` tag.
The value of the
[`building:part`](/wiki/Key:building:part "Key:building:part")`=*` tag
is usually [`yes`](/wiki/Key:building "Key:building"), but it can be any
[`building`](/wiki/Key:building "Key:building")`=*` value (example
[`building`](/wiki/Key:building "Key:building")`=yes`,
[`building:part`](/wiki/Key:building:part "Key:building:part")`=government`
and
[`building:part`](/wiki/Key:building:part "Key:building:part")`=school`
if a building has a part used by the town hall and a room used as a
classroom).

The entire building outline should be filled with
[`building:part`](/wiki/Key:building:part "Key:building:part")`=*`
areas, tagged with their respective height and other attributes. These
areas may overlap each other or may be disjunct, depending on the
building. That said, while 2D footprints can (and often need to)
overlap, avoid overlapping 3D volumes – especially if the volumes have
common faces.

See the following section for building tags typically applied to areas
tagged with
[`building:part`](/wiki/Key:building:part "Key:building:part")`=*`.

Areas tagged with
[`building:part`](/wiki/Key:building:part "Key:building:part")`=*` are
mainly considered for 3D rendering. 2D renderers ignore the building
attribute tags described in the following section.

Tip: Overlapping shapes like this can be tricky to select. In JOSM,
click while holding down 'Alt' key to cycle through overlapping objects
and make the selection you
want.<sup>[<span class="cite-bracket">\[</span>2<span class="cite-bracket">\]</span>](#cite_note-2)</sup>

#### <span id="Underground_parts" class="mw-headline">Underground parts</span>

If a building extends underground *beyond* the outline or footprint
visible above the ground, treat these parts in the same way as
overhanging parts. That is, tag the underground outlines of the building
with [`building:part`](/wiki/Key:building:part "Key:building:part")`=*`
with
[`layer`](/wiki/Key:layer "Key:layer")`=`<a href="/wiki/Tag:layer%3D-1" class="mw-redirect"
title="Tag:layer=-1"><code class="mw-content-ltr"
dir="ltr">-1</code></a> (and the above ground parts with
[`layer`](/wiki/Key:layer "Key:layer")`=`<a href="/wiki/Tag:layer%3D1" class="mw-redirect"
title="Tag:layer=1"><code class="mw-content-ltr" dir="ltr">1</code></a>).
Create a
[`type`](/wiki/Key:type "Key:type")`=`<a href="/wiki/Tag:type%3Dbuilding" class="mw-redirect"
title="Tag:type=building"><code class="mw-content-ltr"
dir="ltr">building</code></a> relation including the
[`building`](/wiki/Key:building "Key:building")`=*` polygon and all the
[`building:part`](/wiki/Key:building:part "Key:building:part")`=*`
polygons. Assign a [`role`](/wiki/Key:role "Key:role")`=`<a
href="/w/index.php?title=Tag:role%3Doutline&amp;action=edit&amp;redlink=1"
class="new" title="Tag:role=outline (page does not exist)"><code
class="mw-content-ltr" dir="ltr">outline</code></a> to the
[`building`](/wiki/Key:building "Key:building")`=*` polygon and a
[`role`](/wiki/Key:role "Key:role")`=`<a
href="/w/index.php?title=Tag:role%3Dpart&amp;action=edit&amp;redlink=1"
class="new" title="Tag:role=part (page does not exist)"><code
class="mw-content-ltr" dir="ltr">part</code></a> to the
[`building:part`](/wiki/Key:building:part "Key:building:part")`=*`
polygons, especially the underground part.

### <span id="Building_relations" class="mw-headline">Building relations</span>

There is no need to create a
[`type`](/wiki/Key:type "Key:type")`=`<a href="/wiki/Tag:type%3Dbuilding" class="mw-redirect"
title="Tag:type=building"><code class="mw-content-ltr"
dir="ltr">building</code></a> relation, i.e. simply position all
building parts inside the building outline. Relation could be useful in
the case where at least one part of a building is hanging over the
building footprint or if the building has a complex structure with lots
of parts, a
[`type`](/wiki/Key:type "Key:type")`=`<a href="/wiki/Tag:type%3Dbuilding" class="mw-redirect"
title="Tag:type=building"><code class="mw-content-ltr"
dir="ltr">building</code></a> relation can be used to group the building
outline and all building parts together.

If the
[`type`](/wiki/Key:type "Key:type")`=`<a href="/wiki/Tag:type%3Dbuilding" class="mw-redirect"
title="Tag:type=building"><code class="mw-content-ltr"
dir="ltr">building</code></a> relation is present for a building, all
building parts must be listed as the relation members with the role
<span class="mw-valign-text-bottom" typeof="mw:File">[<img
src="/w/images/thumb/5/5d/Osm_element_role.svg/20px-Osm_element_role.svg.png"
class="mw-file-element" decoding="async"
srcset="/w/images/thumb/5/5d/Osm_element_role.svg/40px-Osm_element_role.svg.png 1.5x"
width="20" height="20" alt="role" />](/wiki/Relation#Roles "role")</span>` part`.
The building outline must be listed with the role
<span class="mw-valign-text-bottom" typeof="mw:File">[<img
src="/w/images/thumb/5/5d/Osm_element_role.svg/20px-Osm_element_role.svg.png"
class="mw-file-element" decoding="async"
srcset="/w/images/thumb/5/5d/Osm_element_role.svg/40px-Osm_element_role.svg.png 1.5x"
width="20" height="20" alt="role" />](/wiki/Relation#Roles "role")</span>` outline`.
The building parts can be located in any possible way (inside, outside,
intersecting, touching) relative to the building outline in the presence
of the
[`type`](/wiki/Key:type "Key:type")`=`<a href="/wiki/Tag:type%3Dbuilding" class="mw-redirect"
title="Tag:type=building"><code class="mw-content-ltr"
dir="ltr">building</code></a> relation.

If there is no
[`type`](/wiki/Key:type "Key:type")`=`<a href="/wiki/Tag:type%3Dbuilding" class="mw-redirect"
title="Tag:type=building"><code class="mw-content-ltr"
dir="ltr">building</code></a> relation, an application should treat all
building parts within the area of the building outline as part of that
building.

## <span id="Tagging_for_building_outlines_and_parts" class="mw-headline">Tagging for building outlines and parts</span>

The following tags can be used on both building outlines and building
parts.

Tags for buildings/building parts are classified into 3 categories:

- tags for only the roof of the building = tags with the prefix roof:
- tags for only the building under the roof (the facades) = tags with
  the prefix building:
- tags for both = tags with no prefix

## <span id="Software_support" class="mw-headline">Software support</span>

*Main article:* [3D development](/wiki/3D_development "3D development")

Many maps and tools support the simple 3D buildings schema. Among the
first were the [OSM-3D.org](/wiki/OSM-3D.org "OSM-3D.org") renderer in
2009, the [OSM2World](/wiki/OSM2World "OSM2World") renderer and
[Kendzi3D](/wiki/JOSM/Plugins/Kendzi3D "JOSM/Plugins/Kendzi3D") JOSM
plugin in 2011, and the Nutiteq Android 3D Mapping SDK (now
<a href="https://github.com/CartoDB/mobile-sdk/" class="external text"
rel="nofollow">Carto Mobile SDK</a>) and
[WikiMiniAtlas](/wiki/WikiMiniAtlas "WikiMiniAtlas") in 2012.
<a href="/wiki/OSMBuildings" class="mw-redirect"
title="OSMBuildings">OSMBuildings</a> launched a
<a href="https://en.wikipedia.org/wiki/2.5D" class="extiw"
title="w:2.5D">2.5D</a> display in 2012, followed by a 3D version in
2015. In 2013, [F4 Map](/wiki/F4_Map "F4 Map") became the first
browser-based renderer to fully support the Simple 3D Buildings schema.
