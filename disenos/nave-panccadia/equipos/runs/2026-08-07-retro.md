## Run summary

An 18-asset Three.js catalog run built a standalone equipment library for nave-panccadia
(`equipos/<slug>/<slug>.html` + `design-spec.yaml` + `runs/<slug>.png` + a materials `.review.json`).
Every asset PASSED a single materials gate (global 0.76–0.80); no asset ran blockout/structural/
surface/lighting/interaction/optimization or reached P6/P7. Two real defects were found and fixed
in-run (bare stainless reading black; autoRotate poisoning the console-clean check), and the run
could not make `gate-state.mjs` green — it bypassed it and used each asset's materials review JSON
as the done-marker. No scene assembly, no delivery kit, no library extraction happened.

Rationale (why · cost · impact):

- **#1** — The single highest-value finding. The kit's gate model assumes ONE design climbing an
  8-pass ladder; it has no representation for "N independent simple assets, each one gate." The run
  proved this by going dark on gate-state and hand-rolling a done-marker — exactly the "copy under
  fake names / bypass the checker" failure GATES.md §instrument warns about, forced here by a real
  structural gap, not laziness. The `complexity.tier` machinery (DESIGNSPEC.md §Pre-spec) already
  exists but only drives spec DEPTH, not the gate ladder — a natural hook to extend. Low code cost
  (gate-state already parses the spec), high correctness impact (restores a green, auditable gate).
- **#2** — Cheap doc, high recurrence: the run re-derived the identical fix 18× because neither
  §3.1 (metalness rule, no dark-scene warning) nor §3.3 (studio variant uses RectAreaLight, which
  the staged 2026-07-22 row says stalls SwiftShader) gives a headless-safe answer for bare metal.
- **#3** — One-line default change, unambiguous measured failure, prevents a false `console_clean`
  on the first capture of any orbit-enabled asset.
- **#4** — Overlaps #1 (both are the catalog-shape gap); folding a per-asset extraction step in
  prevents the rebuild tax LIBRARY.md exists to stop.
- **#5** — Weakest: transient, self-healed, evidence overwritten. Vendoring is a real change with
  its own tradeoffs. Filed as "consider," not a push.

## Anti-patterns observed

- **Checker bypassed, not fixed** — unable to make `gate-state.mjs` green, the run used the
  materials review JSON as a private done-marker and left `progress.yaml` unwritten. Reasonable given
  the real gap (delta #1), but it means the run's completion is invisible to the kit's own state tool:
  re-running gate-state on any asset today reports "all locked / nothing done." The fix belongs in the
  tool (delta #1), not in more hand-rolled markers.
- **Recipe re-derived 16–18×** — the brushed-stainless block, the shell scaffolding, and the
  autoRotate fix were each copy-pasted across the catalog instead of extracted once (deltas #2/#3,
  extractions above). Pure duplication tax.

## Honest verdict

This run genuinely surfaced TWO structural findings the kit does not cover — the flat-catalog gate
gap (delta #1, the important one) and a headless-safe bare-metal lighting recipe (delta #2) — plus
one cheap, well-measured default refinement (delta #3, autoRotate). Everything else is either already
covered (metalness value, favicon, RectAreaLight stall, probe retry, extraction-is-a-P7-step) or low
signal (delta #5 is transient and self-healed). The parade of bespoke geometry builders (helix dough
hook, balloon whisk, fry-basket cage, deck-stack, 5-star caster base, emissive keypad) is deliberately
NOT proposed for the library: per LIBRARY.md rule #4 the design catalog is the reuse mechanism for
whole single-use silhouettes, and none of these recurred across assets. Proposing them would be the
"retro that always finds something" noise the protocol warns against.
