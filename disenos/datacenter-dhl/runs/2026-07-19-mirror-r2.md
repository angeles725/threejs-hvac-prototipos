## bfcache diagnosis + proof

- **Diagnosis:** DHL had NO teardown at all — the only `dispose` in source is the one-time
  `pmrem.dispose()` after IBL bake (`rg` over `index.html` finds no `pagehide`/`unload`/
  `beforeunload` listener, no WebSocket/EventSource). So DHL was already bfcache-eligible; the gap
  was the ABSENCE of an explicit persisted-aware lifecycle (and a `resyncClock` re-render entry
  point) matching the sibling's approved pattern, which this round adds. The pattern is
  belt-and-suspenders: pagehide pauses the rAF loop cleanly, pageshow re-arms it and re-syncs the
  clock-driven UI at the preserved tick.
- **Proof (CDP, headless Chrome 150 + swiftshader, DHL → cinemex → browser Back):** the restored
  document reports `pageshow.persisted = true`, `window.__DHL_UI__` present, `isRendering() = true`,
  `#viewer canvas` present, `dataset.appReady = true`, **zero console errors**. The app render loop
  **genuinely resumes**: over a 4 s window the deterministic tick advanced `11 → 14`, matching the
  live page's own rate (`3 → 7` over 4 s) on this heavy scene under swiftshader (~0.75 fps). Captures:
  `runs/assets/mirror-r2-bfcache-before-leave.png` vs `mirror-r2-bfcache-after-back.png`.
- **Headless caveat (documented):** a rAF callback injected *fresh* into the restored page via CDP
  did not fire within 4 s (headless throttles newly-scheduled rAF on a just-restored page), but the
  APP's own re-armed loop advances — so an over-short in-script window can read a flat tick even
  though the loop is live. The definitive 4 s probe (and the live-vs-restored rate parity) is the
  proof of resumption; single 0.7 s windows are below one swiftshader frame and are not evidence.

## Judgment calls

- **Clamp values re-anchored** to DHL's approved compact desktop density (identity > literal token
  values), same call the sibling made.
- **Card table break at ≤767** (DHL's existing phone boundary) rather than the sibling's ≤599, so
  the column-fold band is a clean 768–1279 with no overlap — fits DHL's pre-existing tier structure.
- **Chevron column split into `.row-detail-toggle`** (distinct from the kebab `.row-action`) so the
  ≥1280 "hide the toggle" and phone "hide the toggle in card mode" rules target it cleanly without
  touching the kebab columns.
- **Prune left the orphaned CSS classes in place** — removing them is cosmetic and out of scope for a
  behavior round; called out here so a later sweep can take them.
- **bfcache resumption evidence** rests on the 4 s tick-advance + live/restored rate parity, not on
  sub-second windows (documented headless rAF limitation on freshly-restored pages).
